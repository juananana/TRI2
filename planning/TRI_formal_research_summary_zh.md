# 更新世界状态不等于重新绑定操作目标

## 工具型智能体中的时序指称完整性研究总结

英文题目：*Updating the World Is Not Rebinding the Target: Temporal Referent Integrity in Tool-Using Agents*

拟投稿方向：AAAI 2027 Main Technical Track

更新时间：2026 年 7 月 21 日

## 摘要

工具型智能体在执行跨步骤任务时，通常需要先从外部系统中确定操作对象，再刷新环境状态，最后完成写入、回复或更新等动作。现有控制器往往将完整对话、对象标识、选择条件和最新观察一并交给大语言模型处理，却没有明确区分“环境事实发生变化”与“用户授权改变操作目标”。因此，即使智能体已经正确选定了具体对象，也可能在刷新后重新执行原选择条件，把后续动作悄然转移到另一个对象。反过来，简单地永久锁定旧对象，又会破坏用户明确要求刷新后重新选择的任务。

本文将这一绑定后的授权问题形式化为时序指称完整性（Temporal Referent Integrity，TRI）：世界状态的更新本身不应改变已经建立的目标身份，除非用户话语或显式策略授权重新求值。围绕这一问题，研究构建了具有对称语义和受控状态变化的诊断任务，并提出在刷新前编译目标承诺的控制方法。该方法先判断指称应当保持还是延后求值，再记录绑定时间、稳定实体标识及必要的执行策略，使后续环境观察不能无条件覆盖已经形成的身份承诺。

现有实验已形成从问题发现、机制隔离到实际后果验证的完整证据链。受控主实验、独立状态复制、第三模型验证、完整历史强基线、表示与执行消融、人工语义标注、独立改写、SQLite 写入重放以及公开基准审计共同表明：普通结构化记忆即使保留了所有相关信息，也仍可能发生绑定后的未授权换目标；刷新前目标承诺编译能够显著减少这一错误，而主要收益来自编译时机与身份语义，而非单纯增加字段、调用次数或有效性检查。与此同时，公开任务中严格 TRI 机会极少，多指称压力实验也暴露了组合性限制。因此，本文将结论限定为一种受控的、依赖模型与控制器的机制诊断和评测盲区发现，不将其解释为真实部署中的发生率估计或通用安全保证。

## 一、研究背景与引言

大语言模型正在从文本生成器转变为能够查询数据库、调用 API、管理邮件和修改业务状态的工具型智能体。与单轮问答不同，这些系统的操作对象常常不是由用户直接给出稳定 ID，而是通过自然语言描述在某一时刻解析得到。例如，用户可能要求智能体“现在选择优先级最高的未读邮件，刷新邮箱后回复它”，也可能要求“先刷新邮箱，再选择优先级最高的未读邮件并回复”。如果刷新前邮件 A 排名最高、刷新后邮件 B 排名最高，这两条请求面对完全相同的环境变化，却要求不同的最终目标：前者已经把“它”绑定到 A，后者则有意把选择推迟到刷新之后。

现有 Agent 架构容易忽略这一区别。常见做法是保存完整历史、最近一次查询结果、对象 ID 和选择条件，然后在得到新观察后让模型重新决定下一步动作。从信息角度看，模型并没有遗忘旧对象；问题在于控制状态没有说明旧选择条件究竟只是“该身份如何被找到的来源”，还是一条仍应在新状态中执行的查询。当两种含义都以普通文本或松散字段形式存在时，模型可能把已经解析完成的身份重新解释成动态描述。

这一错误不同于初始实体绑定错误、事实记忆丢失或一般性的陈旧状态问题。初始实体绑定研究关心模型第一次是否选对对象；TRI 则严格以初始绑定正确为条件，考察后续状态变化是否得到改变指称的授权。陈旧状态修复鼓励系统吸收最新事实，但最新事实并不自动决定已经承诺的操作对象是否应当变化。动作有效性检查同样不足以解决问题，因为刷新后的替代对象往往完全合法，却不是用户授权的对象。

基于上述观察，本文提出三个核心问题。第一，工具型智能体在已经正确绑定对象之后，是否仍会因为状态刷新而发生可复现的目标漂移。第二，能否通过刷新前编译身份承诺，区分应当保持的指称与应当重新求值的描述。第三，这一机制是否能够跨模型、语言改写和状态结构复现，并最终影响真实工具写入，而不是只表现为离线标签错误。

本文的贡献集中在以下三个方面。

1. 提出并形式化时序指称完整性，将“环境更新”与“指称转换授权”分离，并给出以正确初始绑定为前提的条件化评测定义。
2. 构建冻结的簇级对称诊断，包括保持与重选、稳定与翻转、删除、失效和名称碰撞等状态变化，从而将目标转换错误与初始选择、对象有效性及普通工具错误区分开来。
3. 提出刷新前目标承诺编译方法，并通过三类模型、真实数据库写入、人工语义验证、强完整历史基线、最近邻方法适配和公开基准覆盖审计，系统分析方法收益、错误后果和适用边界。

## 二、问题定义与方法

### 2.1 时序指称完整性

设智能体在状态 S0 中根据指称 r 和选择条件 q 找到实体 e0，随后环境刷新为 S1。若用户在刷新前已经要求选择具体对象并在后续“对它”执行动作，则 e0 已经成为身份承诺；即使 q 在 S1 中返回新的实体 e1，系统也不能仅因环境更新而把目标替换为 e1。只有当原始指令将选择明确推迟到刷新后，或策略明确授权重新求值时，e1 才是正确目标。

因此，控制器需要区分两种状态：一种是尚未解析的查询，后续可以在指定状态中求值；另一种是已经绑定的身份，后续观察只能更新该实体的属性和有效性，不能无授权地改变其身份。TRI 要求任何从已绑定实体到另一实体的转换都有可追溯的语言或策略依据。

### 2.2 刷新前目标承诺编译

本文的核心方法是 Compile-then-Act（CTA），中文表述为“刷新前目标承诺编译”。控制器在读取初始状态和用户指令后，先完成一次语义编译，记录指称的绑定时机、选择条件以及已经绑定的稳定实体 ID。对于保持型任务，选择条件只作为身份来源保存；对于重选型任务，选择被明确保留为刷新后的可执行查询。

类型化生命周期扩展进一步记录保持或重选模式、已绑定目标、无效目标处理策略和动作前置条件。环境刷新后，确定性 gate 可以检查已绑定实体是否仍满足动作要求，并按已编译策略执行、拒绝或授权回退。该 gate 的作用是防止后续 actor 违反正确合同，但不能修复错误的初始 ID、错误模式或不完整的动作 schema。

### 2.3 为什么简单替代方案不充分

永远锁定旧 ID 只能解决保持型任务，在用户要求刷新后重选时必然失败；永远重新执行选择条件则会破坏已建立的身份承诺。仅保存完整历史或全部字段也不能保证模型正确理解字段之间的约束关系。单独加入“保持/重选”标签、普通提前计划或动作有效性检查，同样没有把“描述已经变成身份”落实为可执行控制状态。本文因此不主张某个复杂数据结构本身不可替代，而是主张指称转换决策必须在刷新前显式完成，并在执行边界得到遵守。

## 三、实验设计

### 3.1 研究问题

实验围绕六个研究问题展开：

1. 普通结构化状态在保留完整信息时是否仍会发生绑定后目标漂移。
2. 刷新前目标承诺编译能否提高授权目标准确率并降低条件 TRI。
3. 收益究竟来自刷新前编译、类型化表示还是确定性执行 gate。
4. 现象和方法是否能够跨模型、语言改写、状态簇和新 schema 复现。
5. 目标漂移是否会转化为真实数据库中的错误实体写入。
6. 公开 Agent benchmark 是否已经包含足以观察这一机制的任务机会。

### 3.2 受控任务构造

每个任务包含初始实体表、自然语言选择条件、动作及动作前置条件。生成器先在 S0 上执行选择条件得到初始目标，再施加受控状态变化得到 S1。保持型与重选型最小对共享领域、两个状态、选择器、动作和 schema，只改变用户话语中的绑定时机，从而避免领域难度、实体频率或状态变化解释两类答案差异。

状态变化包括五类：Flip 让另一个有效对象成为新的选择器赢家；Stable 保持赢家不变，用于检测控制器是否对任何刷新都过度反应；Remove 删除旧目标；Invalidate 保留 ID 但使其不再满足动作要求；Name Collision 让不同对象具有相同显示名称，用于检验系统是否依赖稳定身份而非表面字符串。

主实验包含 160 条任务、20 个语言模板簇和 8 个领域。独立复制使用重新冻结的 240 条任务、40 个状态簇和 10 个新 schema，并分别在 Qwen、GLM 和 DeepSeek 三个模型家族上运行。统计分析以完整模板簇或状态簇为重采样单位，不把同一簇内的模板变体视为独立样本。

### 3.3 对比方法与消融

主要比较包括：普通结构化记录、刷新前目标承诺编译、类型化生命周期自由 actor 和带确定性 gate 的生命周期控制器。普通结构化记录保存原始指令、初始 ID、实体快照、选择条件、动作及前置条件，因此不是通过删除信息构造的弱基线。

为定位机制，实验加入只增加 reference mode 的普通记录、非类型化提前计划、仅动作有效性 gate、永远锁定、永远重选、普通完整历史两轮 Agent 以及刷新后显式提醒模型判断保持、重选或拒绝的强语义基线。方法升级实验还测试了事件图和可执行选择器，但两者未达到预先冻结的跨模型门槛，因此没有替换简洁 CTA 主线。

最近邻工作比较以 Binding Drift 官方代码审计为基础。由于其官方运行器依赖 AWS Bedrock，本文在保留官方 re-verification 提示框架的前提下替换模型调用层，并将实验明确标记为 author adaptation，而非官方 Binding Drift 分数。

### 3.4 指标与统计

论文同时报告端到端授权目标准确率、正确初始绑定率、条件 TRI、Stable 控制错误、最终数据库成功、错误实体写入、无效尝试和不必要拒绝。条件 TRI 只统计初始绑定正确、旧目标刷新后仍存在且可执行、选择器赢家发生变化的严格机会，因此其分母会随模型的初始绑定能力变化。

主要区间使用 10,000 次簇级 bootstrap；配对二元结果的 McNemar 检验作为次要统计。所有 API 失败、解析错误和缺失任务按 intention-to-treat 原则计入失败。实验记录冻结数据哈希、模型端点、温度、thinking 设置、请求数、重试、token、延迟及原始响应，保证结论能够追溯到具体运行文件。

## 四、已经运行的实验与结果

### 4.1 主实验：普通结构化状态仍会漂移

在 160 条冻结语言任务上，普通结构化记录在 Qwen 和 GLM 上分别达到 64.4% 和 71.9%；刷新前目标承诺编译达到 95.0% 和 96.2%；类型化生命周期加 gate 达到 98.1% 和 100.0%。这说明即使控制器已经保留原始指令、目标 ID、对象快照和选择条件，把这些内容作为普通状态交给模型仍不足以稳定维持目标身份。

| 控制器 | Qwen3.5 | GLM-5.1 |
|---|---:|---:|
| 普通结构化记录 | 64.4% | 71.9% |
| 刷新前目标承诺编译 | 95.0% | 96.2% |
| 类型化生命周期自由 actor | 96.9% | 98.1% |
| 类型化生命周期 + gate | 98.1% | 100.0% |

对称策略控制进一步表明，永远锁定与永远重选都只有 60.0%，并且错误方向互补。前者能完成保持任务却破坏重选任务，后者恰好相反。这一结果说明问题的关键不是选择“保守”或“及时更新”，而是识别用户是否授权改变指称。

### 4.2 表示与执行机制消融

只在普通状态中增加保持/重选字段时，两模型均为 75.0%；非类型化提前计划为 81.2% 和 70.6%；仅增加动作有效性 gate 为 65.0% 和 73.1%。这些结果均明显低于 CTA 和类型化生命周期方法。生命周期自由 actor 已达到 96.9% 和 98.1%，确定性 gate 只进一步增加 1.2 和 1.9 个百分点。

| 消融方法 | Qwen3.5 | GLM-5.1 |
|---|---:|---:|
| 普通记录 + reference mode | 75.0% | 75.0% |
| 非类型化刷新前计划 | 81.2% | 70.6% |
| 普通记录 + validity gate | 65.0% | 73.1% |
| 刷新前目标承诺编译 | 95.0% | 96.2% |
| 生命周期自由 actor | 96.9% | 98.1% |
| 生命周期 + gate | 98.1% | 100.0% |

因此，主要收益与刷新前完成身份承诺编译有关，而不是多写一个字段、增加一次模型调用或只检查目标是否有效。gate 的价值主要是把正确编译的合同落实到写入边界，而不是产生大部分准确率增益。

### 4.3 240 条独立复制与第三模型

独立复制更换了状态、schema 和任务组合。严格以正确初始绑定为条件时，普通结构化记录在 Qwen、GLM、DeepSeek 上分别发生 43/72、38/80 和 59/79 次核心漂移；CTA 在对应机会中均为 0。三模型方向一致，说明现象不依赖某一个端点或原始语言模板。

| 模型 | 普通记录条件漂移 | CTA 条件漂移 | CTA 相对普通记录的端到端增益 |
|---|---:|---:|---:|
| Qwen3.5 | 43/72 | 0/71 | +23.3 个百分点 |
| GLM-5.1 | 38/80 | 0/70 | +24.2 个百分点 |
| DeepSeek | 59/79 | 0/70 | +17.5 个百分点 |

逐领域和逐模板剔除分析显示，删除任意一个完整领域或模板家族后，三模型的 CTA 相对增益仍全部为正。最新的簇级样本充分性审计进一步按完整簇无放回抽样：主实验只使用 10 个语言簇时，两模型的增益在全部 10,000 次抽样中仍为正；复制实验只使用 10 个状态簇时，三模型增益为正的比例已接近或达到 100%，使用 20 个簇后全部为 100%。完整数据的簇级置信区间均不包含 0。由此可见，当前受控结论并不依赖把同簇模板行错误地当作独立样本，继续增加同质合成行的边际价值较低。

### 4.4 完整历史与刷新后强提醒

为排除普通结构化 ledger 人为诱发错误的解释，研究在同一 240 条任务上运行了两类更接近普通 Agent 的强基线。第一类保留完整对话历史并进行两轮交互，不使用 TRI 术语；第二类在刷新后一次性看到完整状态，并被明确要求判断应当保持、重选还是拒绝。

| 模型 | 普通完整历史 | 刷新后强语义提醒 | CTA |
|---|---:|---:|---:|
| Qwen3.5 | 63.3% | 69.6% | 70.8% |
| GLM-5.1 | 67.1% | 80.8% | 94.2% |
| DeepSeek | 68.8% | 75.8% | 91.2% |

完整历史并没有消除目标替换；刷新后提醒虽然改善结果，却仍在每个模型的 80 个保持型、赢家变化任务中发生 56、38 和 42 次替换。CTA 相对强提醒在 GLM 和 DeepSeek 上具有显著优势，在 Qwen 上仅高 1.2 个百分点且区间跨 0。因此论文不会主张 CTA 在所有模型的总准确率上都显著优于强提示，而会强调刷新前编译提供了强基线缺少的可审计绑定事件，并在初始绑定正确后将三模型的核心条件漂移降为 0。

### 4.5 SQLite 写入后果

目标漂移不仅改变离线预测 ID，还会修改错误的数据库对象。在早期 40 条模型直接操作 SQLite 的实验中，普通结构化记录在 Qwen 和 GLM 上分别产生 13 次和 8 次错误实体写入，生命周期 gate 均为 0。独立复制中，普通记录的 140 次核心漂移全部能够重放为错误对象写入。

六组完整历史及强提醒实验共包含 1,440 个数据库重放 episode。普通完整历史在 Qwen、GLM、DeepSeek 上分别产生 87、79、75 次错误写入；强提醒仍分别产生 70、46、57 次。该实验把“目标指称判断错误”连接到了可观察的系统状态损坏，并说明只要替代对象本身动作合法，普通 validity gate 无法阻止错误。

### 4.6 人工语义验证与独立改写

一名未参与任务设计的志愿者对 50 条指令进行自然英文改写，另外三名盲标者对随机化的 100 条原始或改写任务独立选择目标、拒绝或澄清。标注者看不到任务模式、状态变化类型和 gold。Fleiss kappa 为 0.708，多数票与 benchmark gold 的一致率为 86%，表明保持与重选的核心语义具有较好的人工可操作性。

在 50 条独立人工改写任务上，普通结构化记录在 Qwen/GLM 上为 60%/74%，CTA 为 90%/98%。结果方向与原始模板一致，说明主要效应不只存在于作者措辞中。需要保留的边界是，目标无效后的拒绝策略具有较低的人类一致性，因此核心主张集中在 Preserve/Reevaluate，而不是把所有 fallback 都解释为自然语言共识。

### 4.7 新 schema、条件策略与多指称压力测试

80 条未见 schema 迁移任务使用项目、费用、库存和云部署等新领域及新动作字段，生命周期方法将 Qwen 的结果从 46.2% 提高到 82.5%，说明方法能够迁移，但也暴露了新 schema 下的 selector grounding 和拒绝错误。40 条条件策略任务进一步区分动作有效性 guard 与选择器一致性 guard，支持把有效性和身份来源分开表示。

在多刷新、多指称及监控对象与操作对象并存的压力任务中，标量生命周期方法没有稳定胜过普通方法。加入角色索引后，Qwen 从 35/40 提高到 39/40，GLM 则与较简单方法持平。该负结果明确限定了当前方法的适用范围：现有证据最充分的是控制器编排的、单刷新、单操作目标任务；多角色组合和复杂修复仍需新的表示与实验。

### 4.8 最近邻 Binding Drift 适配

Binding Drift 主要研究初始实体绑定错误及其在工作流中的传播，并提出 Entity Lock 和重新验证方法。TRI 与其保持分支存在重叠，但增加了同状态下必须重选的对称任务，关注的是初始绑定正确后是否授权再次求值。

在冻结的 20 条对称任务上，Entity Lock 类比方法对保持任务为 10/10、重选任务为 0/10；GLM self-reverify 正好相反，为 0/10 和 10/10。这说明无条件锁定与无条件重新解析分别只能解决授权问题的一半。Qwen reverify 仅为 3/20，其中多数错误来自选择器 grounding；冻结 CTA 在 Qwen 和 GLM 上分别为 12/20 和 17/20，是两个模型中唯一在保持和重选两类任务上都取得非零结果的方法。

该比较保留了官方 prompt 框架，但 TRI 必须向 verifier 提供完整时序指令，否则会删除“是否授权重选”这一研究变量。因此它被明确报告为作者适配实验，不是官方 Binding Drift 榜单结果，也不支持 CTA 在初始绑定修复问题上优于 Binding Drift。

### 4.9 公开 benchmark 覆盖审计

研究审计了 ToolSandbox、AppWorld 和 tau3-bench 的公开任务或轨迹。ToolSandbox 的 129 个语义任务家族中没有严格原生机会；AppWorld 的 732 个任务、244 个家族中只有一个 near-match；tau3-bench 的 2,449 个任务和 10,832 条公开轨迹中同样没有严格机会。低干预 AppWorld 工具闭环中，28 次正确且及时的绑定没有出现条件 TRI，少量错误发生在首次选择之前，属于工具顺序问题。

这些结果既不能证明 TRI 在现实中高频，也不能简单说明现象不存在。更准确的结论是，现有 benchmark 很少构造“正确绑定之后发生独立状态变化、同角色竞争者成为新赢家、随后对具体实体执行可评分写入”的机会。一个冻结的 ToolSandbox 兼容干预实验提供了有限桥梁证据：在严格机会中，GLM 普通控制器出现 3/6 次未授权换目标，而匹配 Stable 控制为 0/2；但任务语义和同步事件经过自定义干预，严格审计也是事后完成，因此不能作为自然分布发生率证据。

## 五、当前论文主线与完成情况

论文的核心叙事已经稳定为：工具型智能体可能在正确初始绑定后，把已经解析的身份重新当成动态查询；这一问题不是信息缺失，而是控制器没有显式表示状态变化是否得到指称转换授权；刷新前目标承诺编译能够在受控任务中显著降低错误，并把身份承诺落实到执行边界；公开 benchmark 对这一机制覆盖不足，而复杂多指称场景仍未解决。

目前已经完成问题定义、形式化、主方法、两模型主实验、三模型独立复制、强完整历史基线、表示和执行消融、数据库错误后果、人工语义验证、人工改写、最近邻方法适配、外部 benchmark 审计和负面压力测试。主论文已形成符合 AAAI 篇幅的可编译版本，补充材料已收录详细协议、长表、错误分类、成本、来源追踪和 artifact 映射。

论文当前最有力的证据不是某一个最高准确率，而是互相闭合的机制链条：对称最小对说明不能永远锁定或永远重选；普通记录和完整历史说明错误并非由删除信息造成；表示消融说明单字段和普通计划不足；CTA 与生命周期分解定位主要收益来自刷新前承诺编译；独立状态和第三模型复制排除单一模板或模型偶然性；SQLite 重放说明错误会改变真实系统状态；公开数据审计则界定外部有效性与评测盲区。

## 六、论文仍需改进的部分

### 6.1 进一步收紧主张与术语

正文需要始终区分端到端准确率、正确初始绑定率、条件 TRI 和错误写入率，避免在不同分母之间跳转。TRI 应被表述为“模型与控制器条件下的绑定后机制诊断”，不能写成普遍的 LLM 缺陷、现实发生率或通用 Agent 安全保证。对于 ToolSandbox 兼容实验，应使用“受控干预证据”，而不是“公开 benchmark 上的正向结果”。

### 6.2 强化与最近邻工作的二维定位

相关工作应使用“初始绑定是否正确”和“更新后是否授权重选”两个维度解释 TRI 与 Binding Drift 的关系。本文不争夺初始错误修复赛道，而是说明锁定和重新验证都不能自动回答转换授权问题。正文还需要更清楚地区分 Entity Binding Failures、记忆型 Agent、动态环境适应和动作合同工作，避免把所有邻近研究概括为同一种实体记忆问题。

### 6.3 优化正文信息密度

摘要和引言应保留直观最小例子、问题定义、方法原则与主要结论，减少连续数字和实验清单。主文只保留最能支撑因果链的结果：主实验、机制消融、三模型复制、强基线、错误写入和外部边界。完整切片、样本充分性曲线、Binding Drift 适配长表、成本及失败分类放入补充材料。

### 6.4 补充运行稳定性而非继续堆同质模板

簇级样本充分性分析已经表明 160 条主实验和 240 条复制实验对受控效应具有足够精度。下一步更有价值的是在分层的小规模任务集上重复温度为零的服务端调用，评估端点非确定性和结论方向稳定性；如果资源允许，可增加一个接口稳定、来源独立的模型家族。继续把同一种合成模板扩充到更大行数，对外部有效性和方法新颖性的帮助有限。

### 6.5 谨慎补强外部有效性

可以在不改变任务语义的前提下寻找真实日志或公开环境中的自然 TRI 机会，并由第二名审计者独立复核 strict/near-match/excluded 标签。若无法获得足够自然机会，论文应把“现有 benchmark 缺少可观察机会”本身作为审计结果，而不是为了获得正例扩大后验筛选范围。

### 6.6 保留组合性限制

多刷新、多角色和身份迁移仍是方法边界。后续工作可探索带角色索引的事件图、可执行 selector 和 capability 合同，但本稿不应在没有跨模型稳定结果时把复杂控制器升级为主方法。现阶段简洁 CTA 更符合已有证据，也更容易说明方法收益来自何处。

## 七、总体判断

当前研究已经完成一篇机制诊断型论文所需要的主要闭环：问题能够被严格定义，现象在冻结任务和多个模型中复现，方法具有明确而简单的设计原则，对比和消融能够定位收益来源，错误能够落实为真实数据库后果，人工验证支持核心语义，公开数据审计和负面实验又限制了结论边界。

论文的主要风险已经不再是“实验完全没有跑通”或“数据量明显不足”，而是如何让审稿人认可这一简单控制原则背后的独立研究问题，以及如何诚实处理合成任务占比高、自然机会稀少和组合性有限。只要正文保持窄而清楚的主张，正面处理 Binding Drift 等最近邻工作，并把受控因果证据、外部覆盖盲区和实际错误写入组织成一条连续论证，论文具备继续按 AAAI 2027 标准推进的基础。

## 结论

环境更新改变的是智能体掌握的事实，不必然改变用户已经授权的操作对象。工具型智能体需要把“描述仍是查询”与“描述已经解析为身份承诺”表示成不同的控制状态，并在执行前明确决定是否允许转换。本文的实验表明，普通结构化记忆、完整历史和刷新后提醒都不能稳定承担这一职责；刷新前目标承诺编译在受控条件下提供了更可靠、可审计且可执行的解决路径。现有结果支持将 TRI 作为工具型智能体评测中的一个独立机制与覆盖盲区，但其自然发生率和复杂组合场景仍需要后续研究。
